PDF Q&A App - Backend
=====================

What this is
------------
A FastAPI backend that lets users upload PDF files and ask questions about
them in plain language. Answers are generated by an LLM using only text
retrieved from the uploaded PDFs (Retrieval-Augmented Generation, "RAG"),
and every answer comes with the source page numbers and snippets it used.

It is designed to be used by an Angular frontend (default origin
http://localhost:4200), which is why response fields are camelCase.


How it works
------------
1. Upload
   - A PDF is uploaded to POST /documents (max 20 MB, PDF only).
   - The file is saved to data/uploads/<id>.pdf.
   - Text is extracted page by page with pypdf.
   - Each page is split into ~1000-character chunks (150-character overlap).
   - Chunks are embedded locally with a sentence-transformers model
     (all-MiniLM-L6-v2 by default) and stored in a Chroma vector database
     (data/chroma_data), tagged with document id, name and page number.
   - Document metadata (name, size, page count, upload time) is stored in
     SQLite (data/app.db).
   - Scanned/image-only PDFs with no extractable text are rejected.

2. Ask a question
   - The question is embedded and the 4 most similar chunks are retrieved
     from Chroma.
   - Those chunks are sent to an LLM via OpenRouter (OpenAI-compatible API)
     with a system prompt telling it to answer only from the excerpts and to
     say so if the answer is not there.
   - The answer is returned along with the pages/snippets used as sources.

3. Delete
   - Removes the document's chunks from Chroma, the PDF file from disk, and
     its row from SQLite.


API endpoints
-------------
GET    /health                  Health check
POST   /documents               Upload a PDF (multipart form field "file")
GET    /documents               List uploaded documents (newest first)
DELETE /documents/{id}          Delete a document
POST   /documents/{id}/ask      Ask a question about one document
                                Body: { "question": "..." }
POST   /chat                    Chat across ALL uploaded documents, with
                                optional conversation history (last 10 turns)
                                Body: { "message": "...",
                                        "history": [{ "role": "user"|"assistant",
                                                      "text": "..." }] }

Interactive API docs are available at /docs once the server is running.


Project layout
--------------
app/main.py                 App setup, CORS, router registration, DB init
app/config.py               Settings loaded from .env, paths, limits
app/api/documents.py        Upload / list / delete / per-document Q&A
app/api/chat.py             Multi-document chat endpoint
app/services/pdf_service.py Saving PDFs and extracting page text
app/services/rag_service.py Chunking, embeddings, Chroma, LLM calls
app/database/sqlite.py      SQLAlchemy model and session for document metadata
data/                       Runtime data (uploads, vector DB, SQLite) - not in git


Setup and running
-----------------
1. python -m venv venv && source venv/bin/activate
2. pip install -r requirements.txt
3. Create a .env file in this folder (it is git-ignored):
       OPENROUTER_API_KEY=<your key from https://openrouter.ai/keys>
       LLM_MODEL=openrouter/free
   Optional: OPENROUTER_BASE_URL, EMBEDDING_MODEL,
             CORS_ORIGINS (comma-separated, default http://localhost:4200)
4. uvicorn app.main:app --reload
   The first upload or question is slower because the embedding model is
   downloaded/loaded on first use.


Current limitations
-------------------
- No authentication; all users share the same documents.
- Scanned PDFs (no text layer) are not supported (no OCR).
- Everything runs in a single process with local storage (SQLite + Chroma
  on disk), so it is meant for development/learning, not production scale.
